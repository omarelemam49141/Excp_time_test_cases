# Regular Leave Advance Notice Policy — Backend Test Cases

## Metadata

- Project: `excp-time`
- Feature: `leave-management`
- Layer: `backend`
- Routes: -
- APIs: `/api/Requests`, `GET /api/leave-requests/preview-empty-chargeable-daystc`
- Related code: *Map concrete files during feature updates.*
- Related docs: *See the project documentation indexes for the owning feature.*

## Scope

- Covers create and update validation for regular annual leave with code `"ANNUAL_REGULAR"`.
- Covers tiered advance notice, retroactive starts, non-regular leave types, empty counted leave days, half-day restrictions, and the preview API.
- Empty counted leave day means the employee has no regular attendance time and no attendance breaks. Existing overtime alone does not make the day non-empty.

## Test pages

- Leave request create and update APIs under `/api/Requests`
- `GET /api/leave-requests/preview-empty-chargeable-days`

## Test scenarios

- Regular annual leave for a short range uses tier 1 notice.
- Regular annual leave for a medium range uses tier 2 notice.
- Regular annual leave for a long range uses tier 3 notice.
- Retroactive regular annual leave skips advance-notice validation.
- Non-regular leave types do not use this advance-notice rule.
- Admin notice settings affect validation immediately.
- Empty counted leave days waive advance notice, including overtime-only days.
- Non-empty regular attendance keeps advance notice active.
- Half-day leave is rejected when all counted leave days are empty.
- Preview API matches create validation for the same employee and dates.
- Team leader approval finalizes a leave request, sends the employee a realtime refresh signal, and removes it from pending leave range lookups.
