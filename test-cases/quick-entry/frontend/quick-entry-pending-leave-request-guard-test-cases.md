# Quick Entry Pending Leave Request Guard — Frontend Test Cases

## Metadata

- Project: `excp-time`
- Feature: `quick-entry`
- Layer: `frontend`
- Routes: `/attendance/quick-entry`
- APIs: `GET /api/leave-requests/pending-in-range`
- Related code: `src/app/features/attendance/components/attendance-quick-entry`, `src/app/core/services/leave-management.service.ts`, `src/app/core/services/attendance.service.ts`
- Related docs: `docs/frontend/technical/quick-entry-pending-leave-request-guard.md`

## Scope

- Covers `/attendance/quick-entry` leave eligibility, pending leave badges, floating leave control-panel counts, day-level cancellation, and range leave creation.
- Empty regular attendance means no start time, no end time, and no attendance breaks on a normal workday.
- Existing overtime on an otherwise empty-attendance day does not block `"Mark as leave"`.

## Test pages

- `/attendance/quick-entry`

## Test scenarios

- Pending leave request blocks duplicate leave creation for the same day.
- Overtime-only empty-attendance day remains eligible for leave.
- Canceling a pending leave request refreshes the day back to its eligible state when regular attendance is still empty.
- Admin target-user mode resolves pending leave markers and cancel actions for the selected employee.
- Quick Entry still loads if pending leave lookup fails.
- Leave modal allows a start and end date for a loaded range.
- A newly created pending leave request removes the day from eligible leave actions after reload.
- A team leader approved leave request sends a realtime refresh popup and appears as an approved leave marker after refresh.
- A team leader refused leave request sends a realtime refresh popup and appears as a refused leave marker after refresh.
- A team leader refused leave request appears as a refused leave marker after refresh.
- Floating leave controls count pending leave requests once and navigate between request groups.
