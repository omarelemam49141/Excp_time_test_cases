# Subordinate requests — bulk actions, bulk-bar navigation, and details (frontend)

## Metadata

- Project: `excp-time`
- Feature: `subordinate-requests`
- Layer: `frontend`
- Routes: `/admin-leader/list-requests`
- APIs: -
- Related code: _Map concrete files during feature updates._
- Related docs: _See the project documentation indexes for the owning feature._

## Scope

- Route `/admin-leader/list-requests` when the **Pending** (or equivalent) filter is active.
- **Requests table** tabs: **All**, leave and other generic types — checkboxes, floating bulk bar, **Details** dialog with in-dialog **Previous** / **Next**, and **bulk bar** circular prev/next among selected rows.
- **Overtime requests** tab: same bulk bar pattern when **Pending** is selected (checkboxes, single bulk approve/refuse API call, cross-page selection); **Details** opens the same modal as generic requests — with **Previous / Next** navigation, **Mark for bulk action** button, and **Accept / Refuse** buttons.
- **Clear selection** confirmation before clearing many marks.
- **Layout:** main list stays padded so bottom page controls are not hidden behind the bulk bar.

## Test pages

- /admin-leader/list-requests

## Test scenarios

- Select several pending requests on one page and approve or refuse them together from the bottom bar (one bulk request in the network log).
- Use the **bulk bar** circular **Previous** / **Next** controls to move among **marked** requests: jump to the correct list page, scroll the row into view, see a short highlight on that row; if **Details** is open, it shows the same request.
- Clear bulk selection only after confirming in the dialog; clearing hides the bar.
- Navigate across multiple pages while keeping prior selections, then run a bulk action that covers all of them.
- Open **Details**, move with **Previous** and **Next** inside the dialog, mark or unmark the open request for bulk, then run a bulk action from the bar.
- Keep the bottom bulk bar visible and usable when **Details** is open; page controls at the bottom of the list remain reachable (not permanently covered).
- On the **Overtime requests** tab with **Pending** selected: use checkboxes and the bulk bar like other types.
- In **Arabic** (right-to-left), **Next** is on the **left** of the counter with a **left**-pointing chevron; **Previous** is on the **right** with a **right**-pointing chevron; the bulk bar stays **above** open detail modals so its actions remain tappable.
- Confirm **Details** from **My requests** does not show inbox-style **Previous** / **Next** for stepping through a leader list.
