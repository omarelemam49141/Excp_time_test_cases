# Bulk employee hours report — Frontend Test Cases

## Metadata

- Project: `excp-time`
- Feature: `reports`
- Layer: `frontend`
- Routes: `/admin/reports/bulk-employee-hours-report`
- APIs: -
- Related code: `src/app/features/admin-leader/admin/components/reports/bulk-employee-hours-report/`, `src/app/features/admin-leader/admin/services/user-attendance-report.service.ts`
- Related docs: `docs/frontend/technical/bulk-employee-hours-report-page.md`

## Scope

This document covers the admin bulk employee-hours report page for employee selection (including **Employees** picker list visibility above the filter card edge when **Selected employees** is on), date range filtering (calendar-day request payload), optional salary input (list scoped to the current employee mode), shortage compensation mode selection, optional advanced controls (weekday and weekend accepted overtime vs shortage and deduction order) when shortage mode is **Default** or **Accepted only**, optional **Overtime only** client-side row filter, optional **exclude from summary** (remove employees from the main table and KPI totals while listing them in a separate card with restore actions), **Open single report** (open the employee hours report in a **new browser tab** for the same dates and that employee, matching the Quick Entry handoff), optional **what-if pending overtime** preview (same label family as the single Employee Hours Report), a **stale-results** notice when on-screen totals no longer match the filter controls until **Generate report** runs again, a **collapsible filter panel** (toggle at the top of the filter card; **Generate report** stays visible when filters are hidden), **auto-collapse of filter details and smooth scroll toward the results** after each successful **Generate report**, summary table rendering, **Total net OT** column and KPI (all-status net overtime after breaks), **Actions** column staying pinned at the correct screen side when the table scrolls sideways (right in English, left in Arabic), and a **Fail** error dialog after a failed **Generate report** that shows the server message text when the API returns one.

## Test pages

- `/admin/reports/bulk-employee-hours-report`

## Test scenarios

- Verify admin can run the report for all employees and for selected employees.
- Verify shortage compensation mode selection is sent and reflected in the output (localized option labels in Arabic).
- Verify filter label icons and the report table title icon have visible spacing from text in RTL.
- Verify salary toggle rules (including salary = 0) are reflected as hours-only behavior.
- Verify with **Selected employees** and **Include salary** on, the salary entry list under **Include salary** shows only chosen people.
- Verify KPI summary cards and sticky table header behavior improve result readability.
- Verify **Total net OT** column and KPI appear and reflect the sum of per-row totals.
- Verify chosen calendar dates are sent without UTC day shift (same displayed start/end as Employee Hours Report).
- Verify the what-if control sends `simulatePendingAsAccepted` and refreshes the grid from the server without changing real overtime status.
- Verify with **Default** or **Accepted only** shortage mode, the optional weekday and weekend accepted-overtime vs shortage lists and the deduction-order list appear, and the chosen values are sent when generating; verify those lists stay hidden for **Full waive**.
- Verify optional **Use refused overtime to cover shortage first** checkbox (hidden for **Full waive**); when checked, `useRefusedOvertimeForShortage` is sent and payable OT / effective shortage outcomes change when the employee has both refused OT and shortage.
- Verify the selected deduction order affects the payable split even when weekday/weekend shortage-capacity settings are mixed (for example weekday 1:1 and weekend pay-rate).
- Verify **Overtime only** hides rows with no overtime in any column, keeps KPIs aligned with visible rows, shows an empty message when no row qualifies, works for all employees and selected employees, and stays on after **Generate report**.
- Verify **Exclude from summary** removes a person from the main table and KPI totals and lists them under **Excluded from summary** with **Include again** and optional **Include everyone again**; verify a new **Generate report** clears exclusions; verify excluding alone does not show the stale information notice.
- Verify with **Overtime only** on, someone already excluded still appears in the excluded list even when they no longer appear in the main table.
- Verify **Open single report** on a bulk row opens the employee hours report in a **new browser tab** for the same calendar dates and that employee, leaves the bulk report tab unchanged, and loads the detailed report in the new tab without manually choosing dates there first.
- Verify with **Selected employees** on, opening **Employees** shows the full pick list **anchored to the Employees field**, fully visible past the bottom of the white filter card, and **not** stuck at the top-left of the window.
- Verify in Arabic, when the report table is scrolled sideways, the **Actions** column stays at the **left** edge of the table card (mirror of English keeping it on the right).
- Verify when **Generate report** fails with a known server message, a single **Fail** dialog shows that exact message in the body (not only a generic generate-failed line).
- Verify when **Generate report** fails because the browser cannot reach the API, the **Fail** dialog does not show lines that start with **Http failure response for** or expose the raw request address.
