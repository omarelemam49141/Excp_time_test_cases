# Admin user form — test cases (frontend)

## Metadata

- Project: `excp-time`
- Feature: `user-management`
- Layer: `frontend`
- Routes: `/admin-leader/users/create`, `/admin-leader/users/:userId/edit`
- APIs: `GET api/app/custom-account/check-user-availability`, `GET api/app/custom-account/get-user-for-admin-edit`, `PUT api/app/custom-account/update-user-by-admin/{userId}`, `PUT api/app/custom-account/set-user-password-by-admin/{userId}`, `POST api/app/custom-account/new-user`
- Related code: `src/app/features/admin-leader/admin/components/admin-user-form/admin-user-form.component.ts`, `src/app/features/admin-leader/admin/components/admin-user-form/admin-user-form.component.html`, `src/app/features/admin-leader/admin/components/admin-user-form/admin-user-form.component.scss`, `src/app/core/services/custom-account.service.ts`, `src/app/shared/services/swal.service.ts`, `src/app/features/admin-leader/shared/admin-leader.routes.ts`
- Related docs: `docs/frontend/technical/admin-user-form.md`

## Scope

- Manual cases for the admin create/edit employee stepper form (`admin-user-form`): steps, validation, change tracking, leave protection, inline availability checks, password reset, layout (100% window, phone width, RTL).
- The file name keeps the old `wizard` wording so existing keys and run statuses stay attached.

## Test pages

- `/admin-leader/users/create`
- `/admin-leader/users/:userId/edit`

## Test scenarios

- Create an employee through the three steps, one by one, with validation on every step.
- Edit an employee: free movement between four steps, change tracking, confirm-before-save, discard, leave protection.
- Inline username/email availability and the password generator.
- Password reset with admin confirmation, including the partial-failure path.
- Layout: fits one 100% window, works at phone width, mirrors in Arabic, respects reduced motion.
